## 连续完成的工作

### 1. 主机与环境只读预检

新增 `scripts/check_host_readiness.py`，复用 `scripts/check_deployment_env.py` 现有 env 解析、必填项与插值检查，保持其旧 CLI/API 行为兼容。提供人类报告和 `--json`；每项包含 `id`、`status`、`summary`、`next_action`，状态只用 `pass`、`warn`、`fail`、`unknown`。未知不能算通过。

只读检查 OS/架构、Python/Docker/Compose、daemon 可达性、目标路径写权限、磁盘、用户指定端口、必填配置/插值风险及清单资产存在性。路径权限不得创建探针文件。检查有有限、可解释的超时。不得启动服务、下载、修改配置、生成/嵌入模型、做 OCR 或用 GPU。端口不能远程扫描；无法辨认占用进程时返回 `unknown`，不要把本项目服务已经占用的端口一概判错。没有明确交付阈值时，不自创内存、显存、磁盘最低值。

入口需显式支持 env 文件、安装路径、端口、资产清单以及 `--verify-hashes`；相对资产路径以清单目录为基准，帮助文本说明路径规则。JSON stdout 只能有有效 JSON 对象，命令日志走 stderr 或脱敏结果项。不得输出秘密值、配置正文、完整 Docker inspect、环境变量全集、认证头或原始含参 SQL。退出码要区分成功/仅警告、明确检查失败和调用错误，并在帮助与手册说明。

### 2. 可重复交付包和资产核对

实现最小可用的本地交付包准备工具，不建设完整发布平台或自动下载器。固定/记录应用、前端、PGVector、Redis、Ollama 镜像版本和目标平台；清点模型、嵌入、OCR 资产、迁移校验、清单 hash、许可证及依赖摘要。可打包用户明确提供或本机已构建的资产；操作前显示待收集文件、预计总量、目标磁盘空间和写入路径。不得自动外联下载，不得把客户资料、`.env`、令牌、口令、私钥或密钥混进可分发包。

若无既有 manifest，给出最小 JSON 样例，例如：

```json
{
  "assets": [
    {"id": "backend-image", "kind": "docker-image", "reference": "enterprise-brain:local", "platform": "linux/amd64"},
    {"id": "ollama-model", "kind": "file", "path": "models/model.tar"},
    {"id": "offline-bundle", "kind": "file", "path": "delivery/images.tar"}
  ]
}
```

示例不代表资源真实存在。元数据检查与字节 hash 校验分开报告。默认只核文件存在、类型、实际大小和镜像在本机 daemon 中是否可见；只有显式 `--verify-hashes` 才读文件字节，并先展示总待读字节数。清单 `size_bytes` 必须与实际匹配；`sha256` 必须是 64 位十六进制，非法即失败；缺预期摘要不得声称完整性已验。镜像 tag/digest 字段存在本身不证明实际字节。模型归档存在不代表 Ollama 已登记可用模型，按资产用途分项说明。静态清单齐全不等于离线安装成功。

### 3. 独立目标安装与离线验证

提供明确的`plan`/`apply`或等效执行边界：计划阶段只读列目标身份、平台、目录、项目名、端口和卷，执行阶段仅针对你自有或业主明确指定的独立目标。独立Compose项目名和端口不能代替硬件资源隔离；同一宿主机的VM、Docker daemon、CPU/GPU/磁盘仍可能争用，不得因此影响主控测试。不得因仓库给出`ssh vm`就视为获准操作共享VM；不得触碰主控当前站点、模型、训练、卷、Cloudisk或其他程序。无法满足独立资源时先推进不依赖目标的工具和说明，一次列出缺少条件。

若暂时没有可用独立目标，先完成工具、样例、预检和离线包核对，在本批交付中一次性列明“真实目标安装未验”及所需条件，继续其它任务；不要写成部署完成。可用自己的本地模型、CPU/GPU 与隔离资源，不使用主控模型端点或训练负载，不启用云回退。

在隔离目标上按固定基线演示代表性真实链路：登录、上传受控合成材料、检索原文、表格计算、下载并核对原报告。明确标记合成资料，不能重跑 C18 或把旧历史测试当本轮通过。操作性变更只在已确认的独立目标上执行；影响未知数据的步骤先停下并单独请求授权。

### 4. 升级、重启和回滚编排

实现可执行的升级/重启/恢复步骤或协调命令，覆盖当前包与上一可运行交付包。锁定镜像版本和 schema 兼容关系；升级前确认备份完成，迁移只执行一次，记录阶段、失败状态、服务版本和恢复建议。对比升级前后已有会话、任务、权限、成果和旧报告字节。

明确区分镜像回滚与 schema/数据恢复：仅切回旧镜像不代表数据库 schema 可逆；schema 不兼容须由隔离备份恢复流程处理。只在自己的隔离目标演练。若 `app/**` 或 `migrations/**` 的缺陷阻塞，记录精确依赖与最小补丁建议，继续不依赖它的交付工作；不得篡改业务语义或绕过失败。

### 5. 完整备份与隔离恢复

恢复到隔离目录和隔离数据库，不覆盖备份源。口令、证书、受保护配置单独管理，绝不进入交付包或证据。恢复验证检查授权边界、原文 hash、计算/会话背景和历史 PDF 字节。若现有核心能力不足，准确说明受影响结果和缺少的接口，不宣称恢复通过，也不扩大到禁止修改的业务层。

### 6. 脱敏本地诊断
