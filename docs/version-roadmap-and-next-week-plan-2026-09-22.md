## 1. 先读这份文档

本文件覆盖旧的版本路线和时间估算。本文件回答四件事：

1. 项目分成哪些版本；
2. 当前只需要做到哪个版本；
3. 多 Agent 如何并发施工；
4. 按当前实际进度，各版本何时完成。

所有 Agent 必须遵守：

- 当前只追 V1，不以 V2～V5 的工程质量要求阻塞功能开发；
- “有代码”“有测试”“计划写过”不等于功能已完成；
- 性能数字必须标记为 `[实测]`、`[算术]`、`[推算]` 或 `[目标]`；
- 未经目标机器实测的秒数不能写成对外承诺；
- 当前前端由前端线负责，未经明确授权不得修改 `frontend/`；
- Chroma 是过渡向量库，不能在新文档中写成最终生产架构；
- PGVector 已进入当前架构，但“已接入架构”不等于“已切换生产读路径”；判断完成度时必须区分迁移、向量镜像/双写、影子验证和正式切读；
- 不得为了显示绿色而使用 `skip`、`xfail`、假数据或静默降级；
- 每项完成都必须有代码、测试或真实环境证据。

权威资料：

- 当前功能和风险：`docs/current-functionality-2026-09-10.md`
- 当前性能实测：`docs/perf/latency-budget-2026-09-16.md`


## 4. 版本定义

### V0：技术原型版

定位：证明技术链路可行。

必须具备：

- FastAPI 和 Vue 可以启动；
- 本地账号登录；
- 文档上传和基础文本解析；
- Chroma 检索；
- Ollama 问答；
- Excel/CSV 基础读取；
- 基础图表；
- PDF/Excel 导出；
- Multi-Agent 基础调度；
- SSE 或等价的处理中状态。

允许存在：

- 内存或 JSON 回退；
- 固定演示数据；
- 单用户；
- 权限不完整；
- 复杂文件不支持；
- 失败后需要重新操作。

V0 验收主线：

```text
登录 -> 上传文档 -> 提问 -> 返回回答
     -> 上传 Excel -> 分析 -> 图表 -> 导出
```

当前项目已明显超过 V0。

### V1：核心功能演示版（当前目标）

定位：先把核心业务功能做成可连续演示的版本。性能、安全和生产级恢复不阻塞本版本。

#### V1 必须能演示的业务主线

```text
登录
  -> 工作台
  -> 上传制度文档
  -> 文档问答并看到来源
  -> 上传 Excel/CSV
  -> 指标统计和数据问答
  -> 生成图表
  -> 导出报告
  -> 查看一条异常或告警结果
```

#### V1 功能要求

登录和工作台：

- 登录页可用；
- 演示账号或本地账号可用；
- 工作台有明确的文档、数据、问答入口；
- 不出现明显死链接、空白页或技术异常串；
- 无数据时显示空态，不用假数字填充真实业务区域。

文档知识库：

- 支持 PDF 普通文本、DOCX 普通文本、TXT、Markdown；
- 支持上传状态、文档列表、搜索、预览、下载和删除；
- 支持基于文档提问；
- 回答可以看到文件名或来源信息；
- 上传失败、解析失败、索引失败要有稳定错误状态。

数据分析：

- 支持 Excel/CSV 上传、列表和预览；
- 支持字段、行数、列数、缺失值和基础统计；
- 支持合计、均值、排名、分组和趋势；
- 支持根据自然语言生成分析结论；
- 只分析用户明确选择或系统明确绑定的数据文件。

图表和报告：

- 至少支持柱状图、折线图、饼图；
- 图表能在对话或结果区域显示；
- 图表可下载；
- 可生成 PDF 或 Excel 报告；
- 报告至少包含标题、数据来源、结论、图表和生成时间。

Multi-Agent：

- 至少能体现问题分类、文档 Agent、数据 Agent、图表 Agent 和结果汇总；
- 页面显示当前步骤、处理中、成功、失败和等待确认；
- 长任务不会无限等待；
- 用户可以取消或离开当前流，回来后不会拿到另一轮的错误结果。

异常和告警：

- 至少有简单规则；
- 支持手动执行检查；
- 能展示异常结果或明确的暂无结果；
- 不使用固定异常数字冒充真实检测结果。

#### V1 允许的技术边界

- 单机、单企业、单租户；
- 本地 Ollama；
- Chroma 作为当前过渡读路径；PGVector 已有迁移、向量镜像和双写基础，但尚未完成生产切读；
- 本地文件存储；
- PostgreSQL/Redis 只在已有链路需要时使用；
- 基础角色权限；
- 基础日志和部分 Trace；
- 复杂任务可以进入队列；
- 可以用演示数据，但必须明确是演示数据。

#### V1 明确不做

- OCR 和扫描 PDF；
- PDF 表格识别；
- 复杂 Word 表格结构化；
- Excel/CSV 进入知识库索引；
- 完整知识图谱工作区；
- 审批工单和审批流；
- 多租户 SaaS；
- 高可用集群；
- 完整灾备；
- PGVector 全量切读；
- 完整 RAG 调试台；
- 完整评测平台；
- 生产级安全认证；
- 任何未经实测的“所有问题几秒返回”承诺。

补充口径：

- “PGVector 全量切读”不在 V1，并不表示 PGVector 尚未进入架构。当前代码已有
  `migrations/0010_pgvector_chunks.sql`、`app/rag/pg_store.py` 和双写接入；
  但 `app/rag/indexing.py` 的 `INDEX_BACKEND` 仍为 `chroma`，检索仍走 Chroma。
- PGVector 的影子验证、R59 切读以及后续停止 Chroma 写入/退役，均不能仅凭计划文档视为已完成；
  必须以当前代码、迁移状态、真实双写数据和可重跑的对比结果为证。
- OCR 当前也不能按“计划中写过”计为已完成。当前 `app/rag/loader.py` 没有扫描 PDF/图片检测、
  OCR 引擎、置信度或 OCR 文本入索引链路；因此 V1 不承诺 OCR，V2 才安排实现。

## 5. 多 Agent 并发施工计划

### 5.1 总控规则

总控不以 Agent 返回“完成”作为完成依据，只认：

1. 写集没有越界；
2. 子树有实际 diff；
3. 定向测试通过；
4. 合并后主树复验通过；
5. 真实环境任务有明确证据或明确标记未验收。

并发上限按写集划分，不按功能名称划分。两个 Agent 如果会修改同一入口、同一契约或同一测试文件，必须串行。

### 5.2 V1 并发组

| Agent 组 | 主要范围 | 完成定义 |
|---|---|---|
| A：问答链路 | Agent、聊天 API、SSE、取消和超时 | 文档问答、状态和取消可复现 |
| B：文档链路 | 文档目录、上传状态、来源和错误态 | 上传、索引、来源、预览和失败态闭环 |
| C：数据与产物 | 数据分析、图表、报告 | Excel/CSV 到分析、图表、报告连续成功 |
| D：告警与演示数据 | 告警规则、检查结果和样例资产 | 至少一条真实规则链路 |
| E：前端验收 | 前端线授权写集 | 登录、问答、数据、图表、报告和错误态可操作 |
| F：测试与性能 | 新测试、性能记录和演示脚本 | 20～25 条题目有真实记录 |
| 总控 | 契约、合并、镜像和真实环境 | 主链路连续跑通，主树复验通过 |

V1 串行门：

```text
在途任务收口
  -> 接口冻结
  -> 镜像重建
  -> admin/普通用户冒烟
  -> 真实模型采样
  -> V1 候选冻结
```

## 6. 性能要求

### 3.1 性能指标的单位

每个性能数字必须说明：

- 测试机器；
- 模型和模型是否冷启动；
- 数据集规模；
- 问题类型；
- 并发数；
- 是否命中缓存；
- 是首字、首个有效事件还是完整结束；
- 是平均值、P50 还是 P95。

“首字”指用户第一次看到有效回答内容的时间。
“完成”指最终回答、来源和必要的图表状态均已返回。

### 3.2 各版本性能门槛

| 版本 | 快速问题 | 普通问答 | 复杂问答 | 并发 |
|---|---|---|---|---|
| V0 | 不要求 | 180 秒内可接受 | 300 秒内可接受 | 1 人 |
| V1 | 首字 10 秒、完成 30 秒目标 | 首字 20 秒、完成 60 秒目标 | 完成 120 秒目标 | 1～2 人演示 |
| V2 | P95 8 秒 | P95 30 秒 | P95 90 秒 | 5 人以内 |
| V3 | P95 5 秒 | P95 20 秒 | P95 60 秒 | 10～30 人，需真机压测 |
| V4 | P95 3 秒 | P95 10 秒 | P95 30 秒 | 以目标硬件压测为准 |

表中 V1 数字是开发演示目标，不是所有设备的硬承诺。
V2 及以上的 P95 只有在样本达到 100 条且完成真实环境测试后才可以对外使用。

### 3.3 V1 的问题分档

快速问题：

- 单一制度事实；
- 单字段合计、均值、排名；
- 简单闲聊。

处理原则：

- 规则优先；
- 一次检索或直接 pandas 计算；
- 最多一次模型回答；
- 不默认 Supervisor；
- 不默认多路查询改写。

目标：完成 30 秒内。

标准问题：

- 普通文档问答；
- 单数据集分析；
- 简单图表。

处理原则：

- 一次路由；
- 一次检索或计算；
- 必要时才改写或重排；
- 一次最终回答。

目标：完成 60 秒内。

深度问题：

- 跨文档；
- 跨数据集；
- 制度和经营数据结合；
- 复杂报告或审批建议。

处理原则：

- 允许 Multi-Agent；
- 允许进入可靠队列；
- 必须持续发送步骤或状态；
- 必须有超时、失败和降级结果。

目标：完成 120 秒内；超时不能无限等待。

### 3.4 当前性能事实

当前已有性能记录显示：

- `[实测]` 复杂文档问答曾达到约 160.6 秒；
- `[实测]` 数据分析请求曾达到约 47.6 秒；
- `[实测]` 一次问答中模型往返约占总时长的 99.5%；
- `[实测]` 检索本体约 0.24 秒，不是当前主要瓶颈；
- `[实测]` 纯 CPU 本地模型存在上下文、生成速度和并发限制；
- `[实测]` 当前正在持续补齐阶段耗时、队列压力、缓存命中和 RAG 结果形状读数。

因此 V1 的性能工作顺序是：

1. 简单问题绕过无用的完整 Multi-Agent；
2. 多路改写按条件触发；
3. 限制每次模型调用的输入和输出预算；
4. 超时后停止继续发起无效模型调用；
5. 让答案分片尽早到达前端；
6. 再考虑缓存、GPU 和 PGVector。

禁止把“更换向量库”当成当前问答提速的主要手段。

### 3.5 V1 性能验收

至少准备以下问题集：

- 5 条快速文档问题；
- 5 条普通文档问题；
- 5 条快速数据问题；
- 5 条普通数据问题；
- 3 条图表问题；
- 2 条复杂综合问题。

每题记录：

```text
问题类型
模型
冷启动或热启动
并发数
首个有效事件耗时
完整耗时
检索耗时
模型耗时
是否命中缓存
是否降级
是否失败
```

V1 不需要伪装成正式 P95 报告，但必须能看出：

- 快速问题没有无故走深度链路；
- 普通问题不会静默等待 5 次模型调用；
- 页面能看到处理中状态；
- 超时会明确结束；
- 两人同时演示时不会永久挂死。

## 9. 版本完成判据

### V1 完成

- 核心主链路连续成功；
- 真实模型至少有一条可复现问答；
- 文档、数据、图表、报告和告警都能得到真实或明确空结果；
- 来源、失败、超时和取消状态可解释；
- 有一次真实性能记录；
- 不把 OCR、PGVector 全量切读或生产安全冒充已完成。

### V2 完成

- OCR、复杂文件、Excel 知识库、图谱、审批、通知和 PGVector 功能入口可用；
- 每项至少有一条真实输入到真实结果链路；
- 失败状态、来源和质量状态可查看；
- 不依赖固定业务数字。

### V3 完成

- 内部用户可以连续使用；
- 资源、权限、队列和恢复闭环成立；
- 重启不丢核心数据；
- 越权测试为 0；
- 失败任务可定位、重试或进入死信。

### V4 完成

- 生产部署、迁移、授权、安全、备份、恢复、监控和压测均有真实证据；
- PGVector 生产读写和 Chroma 退役可回滚；
- 在冻结镜像上通过安全和长时间运行验收。

## 10. 给 Agent 的执行口径

每次接任务先回答：

1. 这项工作属于 V1、V2、V3、V4 还是 V5；
2. 它是否已经在主树完成；
3. 它的写集是什么；
4. 能否与其他 Agent 并行；
5. 最小真实验收链路是什么；
6. 需要什么串行集成门；
7. 结果是代码完成、测试完成，还是环境验收完成。

当前优先级：

```text
V1 主链路
  > V1 真实环境验收
  > V2 功能覆盖
  > V3 内部连续使用
  > V4 生产质量
  > V5 平台增强
```
