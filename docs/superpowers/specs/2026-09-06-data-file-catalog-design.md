# 数据分析文件列表设计

## 目标

为数据分析模块增加独立的数据文件管理区域，使用户能够查看、选择、预览和下载已经上传到 `data` 目录的 Excel/CSV 文件。

数据分析文件与知识库文档分开管理：

- 知识库继续管理 `.txt`、`.pdf`、`.docx`、`.doc`。
- 数据分析模块管理 `.xlsx`、`.xls`、`.csv`。
- 数据分析文件不进入 Chroma 知识库索引。

## 页面设计

数据分析模块采用“左侧文件列表 + 右侧数据预览”的结构，保持与知识库模块一致的视觉语言。

左侧文件列表：

- 显示 `data` 目录下的支持格式文件。
- 每项显示文件名、文件大小和更新时间。
- 当前选中的文件有明确高亮状态。
- 上传成功后自动刷新列表并选中刚上传的文件。
- 空列表时显示上传引导。

右侧数据区域：

- 显示当前文件名。
- 显示行数、列数、缺失值等数据画像。
- 显示表格预览。
- 提供“打开”和“下载”操作。
- 文件解析失败时显示明确错误，不清除已有列表。

## 后端接口

新增：

```text
GET /api/v1/data-files
```

返回 `data` 目录下的数据文件列表，字段包括：

- `filename`
- `size`
- `size_label`
- `modified_at`
- `extension`

现有接口继续使用：

```text
POST /api/v1/upload-excel
GET  /api/v1/data-files/{filename}/preview
GET  /api/v1/data-files/{filename}/file
```

文件名必须继续经过 `_safe_data_filename` 校验，禁止路径穿越。列表接口只返回普通文件，并过滤不支持的扩展名。

## 数据流

1. 页面加载数据分析模块时请求 `GET /data-files`。
2. 后端扫描 `DATA_DIR` 并按更新时间倒序返回文件列表。
3. 页面默认选中最近修改的文件并请求预览。
4. 用户点击其他文件时请求对应预览接口。
5. 用户上传文件时调用现有 `POST /upload-excel`。
6. 上传成功后重新请求文件列表，并加载新文件预览。
7. 打开使用 `inline=true`，下载使用默认附件响应。

## 错误处理

- 未登录访问仍由现有鉴权中间件返回 `401`。
- 数据目录不存在时自动创建并返回空列表。
- 不支持的文件格式不进入列表。
- 单个文件读取失败不影响其他文件显示。
- 预览请求失败时保留当前列表，并在右侧显示失败原因。
- 文件已被删除或移动时刷新列表并提示文件不可用。

## 测试验收

后端测试：

- 列表只返回 `.xlsx`、`.xls`、`.csv`。
- 返回文件名、大小和修改时间。
- 空目录返回空列表。
- 路径穿越仍被拒绝。
- 上传成功后新文件可在列表接口中找到。

前端测试：

- 数据分析标签页能显示文件列表。
- 点击文件会更新预览内容。
- 上传完成后列表自动刷新。
- 打开和下载按钮使用当前选中文件。
- 空列表、加载中和解析失败状态可见。

手工验证：

- 使用管理员账号登录前端。
- 进入“数据分析”。
- 确认 `2026_business_analysis_test.xlsx` 出现在列表。
- 点击文件后确认显示 6 行、8 列和数值字段统计。
- 刷新页面后文件列表仍然存在。
