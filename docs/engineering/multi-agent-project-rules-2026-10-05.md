# 多 Agent 大项目开工规则（2026-10-05·病根复盘成品·供新项目第一天使用）

**用途**：本文件是从「企业智脑」这 33 天（09-03 起 1,300 枚级以上提交）的病根里抽出来的可复用规则集。老项目按 §C 的迁移单逐步收敛，新项目直接按 §A 开局。
**编制口径**：每条规则后面必须跟着「它在旧项目上花掉的实际代价」和「谁来自动执行」。没有量具的规则不算规则，算愿望。

## 0. 一条定律

系统的元成本 ≈ **「需要被相信的说法数」×「每条说法的验证成本」**。
散文里的说法数没有上限，验证成本由单线程总控付且只增不减（棘轮）。所以治法不是「让 Agent 少写」，而是**从源头取消「散文承载真相」这个类别**：任何真相要么住在机器可执行的结构里（代码／schema／行级结构化记录），要么就不配被称为真相，只配叫叙事——叙事不配钉。

## A. 七条硬规矩（新项目第一天就写进 AGENTS.md）

- **A1 状态只住行级结构化记录。** `tickets/RNNN.yaml`（`id/title/write_set/criteria/status/seat/base_sha/evidence`）或一枚 SQLite `ledger.db`。看板 `.md` 是**生成物**，手改生成物＝违规。人类要看表 → 生成视图；要改状态 → 改行。
  代价：本项目看板 7,049 行／跟进单 1,335,486 B，每班开工整本重读，名册靠「行 splice＋竖线＝7＋保留 BOM」手改，改一次赔一次。
  量具：一枚派生校验钉——重跑生成器，产物与盘上那份逐字节相等，不等就红并点名差在哪一行。
- **A2 禁止手抄坐标，跨引用一律派生。** 只许 `文件::符号`／`§键名`／`ticket-id`；CI lint 直接拒 `文件:行号` 和散文里的「枚数」（数值必须由脚本算出来再写进生成物）。
  代价：整类纯返工单不产生任何功能——R660 重锚 46 枚、R646 换 15 枚、R638 棘轮返工、R630/R635 改派生锚。
  量具：`docs/**` 与 `*.md` 扫 `文件:[0-9]+` 形态，命中即红。
- **A3 契约住 schema，不住散文。** API 契约＝`openapi.yaml`＋JSON Schema＋`examples/` 目录，一致性由**生成器**和 diff 校验保证（FastAPI 本来就吐 OpenAPI，散文契约应当是它的投影）。
  代价：本项目 `docs/api/contract-v1.md` 是 500 KB 级单文件，一致性靠用例读 markdown 守。外部复核给的口径是「全套用例 42% 在读 markdown」——**这个枚数占比本班未证**（要 collection 才能枚数级复算），但「测试读散文」这一族的存在与文件体量是现取事实。
  量具：`openapi.json` 与落盘 schema 逐字段 diff；散文只留人话解释，不留可核对的数字。
- **A4 验证只验可执行物，永不验描述。** 「这段注释有没有说谎」是无限验证面（措辞永远能变）；「这个函数在这个输入下抛不抛」是有限验证面。想保护一个说法 → 把它改写成行为测试或 schema 断言；改写不了，就承认它是叙事，不许为它钉用例。
- **A5 棘轮必须双向＋成本内化。** 每枚用例声明「它因哪个产品行为而红」；声明不了的（纯文档针）带 TTL 与到期评审。套件设**预算**：全量门墙钟 ≤ N 秒、每模块用例数 ≤ 比值；超预算时加一条要指名删一条。
  代价：打钉在本项目博弈里占优，因为收益归当下这单、成本归未来所有并树（公地悲剧）。现取形状：`tests/**` 697 个 py 文件里 **564 枚叫 `test_r*.py`**（按工单号生成的针），`app/**` 只有 120 枚 py；最近 200 笔新增行里产品码占 **2.7%**。
  量具：预算就是 CI 的一条红线，超线红；把成本还给作者。
- **A6 作者提交、审查者看 diff、合并排队。** 执行层在**自己的 worktree**里自己 commit（保留 blame 与归因），总控只审 diff，合并交 merge queue 跑一次。
  代价：本项目「执行层一律不得 commit＋总控独担验收亲自复跑」＝吞吐压进一颗脑子；并树/日 09-26 的 76 → 10-05 的 15。未提交的活在别的 Agent 树里一崩就白干（09-17 的 be-r20／be-r53、10-05 的 R666 都是这个形状）。
  🔴 老项目采纳 A6 之前必须业主要素点头：本项目 10-05 起改为「执行层可在**自己的树** commit，主树仍只有总控能动；主树并树仍由总控验收后代提交」。
- **A7 派工＝指针，不是载荷。** 消息 ≤200 B，只写「读 `tickets/RNNN.md`，写域 X，基点 Y」。写不进 200 B 的东西是规格，规格住文件。
  代价：本项目两枚执行层死在长消息投递本身、零写入（事故 #112／#113），整轮报废；还有 R637→R640、R659→R672、R390 作废三枚「中途改判据只能另立单号」的同族报废。

## B. 两条与 LLM 特别相关

- **B1 让遗忘无害。** 假设 Agent 每轮都会失忆：它必须知道的一切都在一枚指针之后且可再生；它绝不能丢的一切都由机器派生。本项目三次线程之死（消息 id 污染、compaction、席位失联）都是这条没满足的直接后果。
- **B2 别把编排故障记进项目史。** 分三本：**产品缺陷**（配测试）／**编排故障**（配框架改动，不编进项目史）／**流程违规**（配规则修订）。本项目事故编号到 #122，其中大头是 provider 兼容、投递死、抄错 id、误杀 pytest——超过三成在说自己的管道。正确响应是**换掉那个管道用法**，不是给它编更多号。

## D. KPI 换掉，否则下次还长回同一个形状

别再拿「并树数／结案纸数」当产出。只看四个数加一条红线：

1. **用户可观察行为的变化数**（产品码 diff 行数／路由数／契约面）；
2. **单枚工单的验证墙钟**（本项目现读：窄验证约 2 分钟/件，全量门 1,592.0 s 且曾要求双态两遍）；
3. **每轮必读台账字节数**（本项目现读：跟进单 1,335,486 B＋看板 7,049 行）；
4. **并树/日**（本项目 76 → 15，管它的是 A5／A6，不是台账机器化）；
- 🔴 红线指标：**读 markdown 的用例占比**。健康值应是个位数；这条线一涨，就是在重蹈同一个病。

## E. 并行度目标本身要改

真实并发 = **min(在飞席位数, 验证吞吐)**。旧规同时写着「默认并行度不低于 3」和「验收由总控独担」——这两条互斥：验证吞吐＝1 时，投 4 枚只是让它们在写集咽喉上互相堵（本项目咽喉＝`app/api/v1/chat.py`、`app/agents/nodes.py`、那本 500 KB 级契约、同一族常驻钉）。

**并行是代码结构的属性，不是 session 数。** 想真提并行度，改的是架构：小模块、按特性分路由、契约分片、写域所有权表（R684）。按功能名称分组的并发组表已废——并行只能按写集切。
