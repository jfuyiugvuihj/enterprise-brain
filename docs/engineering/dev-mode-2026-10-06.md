# ADR：开发模式改章（2026-10-06·业主授权）

**状态**：已采纳。取代「病根处置」①—⑯（原文 `git show HEAD~1:AGENTS.md` 可查）。

## 背景：量出来的病

- 最近 200 笔提交：`app` +2,990 行、`tests` +48,716、`scripts` +26,822、`docs` +29,324。产品码只占新增行的 2.7%，200 笔里只有 21 笔碰过 `app/`。
- 全量门常年红：10-06 夜收 72 failed／11,827 passed，其中约 60 枚红断言的是「文档表格 == 代码现读行位 == 账本数字」——它们测不出用户价值，只防编数，却让「V1 是否验收」这句话无限期挂住。
- 一次实测：走查件在同一轮里收到 38/13/299 帧，屏幕上 0 行——11,827 枚绿针没测出这个。这就是业主问「你这样没问题吗」的那一格。
- 规矩本身成了成本：每枚改动要穿过越来越厚、只能整本重读的台账；重锚行号的纯返工单已经生了三枚（R660 重锚 46 枚／R646 换 15 枚／R638 棘轮）。

## 决定

1. **完成的定义换成可演示**：真容器·真模型·真浏览器里演示得出来，且最终内容与下载产物符合下文质量验收才算绿；废除「码在树／读数待窗」这类中间态。
2. **门分层**：端到端冒烟（九条旅程，分钟级）是唯一进度源；全量回归降级为夜间产品回归；账面坐标族永久出门，改为退出码恒 0 的自检。
3. **待办只看一张表**：`docs/backlog.md`，一行一个可演示功能或缺陷；工单索引只当历史事实。
4. **派工按功能切**：一枚单＝一条旅程里一个看得见的行为＝一个 PR 大小的改动；验证预算 ≤5 分钟，超预算就是写集切错。
5. **元成本上限**：测试＋文档新增行数不得超产品码 3 倍（超了要业主裁定）；不再新增凭据纸、事故编号、行号棘轮、账面自证测试。
6. **汇报口径**：能演示几条／9、不能的各差哪一行码、今天合了哪几条功能、要业主做什么。不报 passed 枚数与并树枚数。

## 保留不动的

反证钉存量不许摘；只有业主能做的六件不代做；坐标一律 `文件::符号`；读数在飞禁改 HEAD；跑窗/跑门与执行层跑件互斥；`app/**` 并树后必须重建镜像＋recreate 才作数；并发 3～4 枚、派工词 ≤200 字节只送指针。

## 后果

- 好处：进度第一次变成「业主能自己点一遍的东西」，而不是需要被相信的说法数；红集合与产品状态解耦，不再出现「门红但产品照跑」和「针绿但屏上没字」两种假账。
- 代价：账面自证这道「防 agent 编数」的闸变松，改由冒烟用例＋演示时的屏幕截图承担；历史 43 号账尺（`scripts/audit_plan_ticket_ledger.py`）不再是进度口径，只作追溯用。
- 立即可见的一步：镜像重建 → `python scripts/smoke_v1.py` → 逐条给「能演示／不能／差哪一行」。

## 生成内容与产物质量验收（2026-10-12·业主要求补充）

适用于问答、分析、图表、PDF/Excel、评测报告，以及告警、通知、Trace、图谱、计算记录等用户可见输出。目标是内容可信、请求完整、表达清楚、成果可用，不以字数、页数、彩色像素或测试数量代替质量。本节是验收与后续生成实现的要求，不代表产品已实现；现有冒烟脚本尚未覆盖全部判据。

### 1. 四项验收与硬失败

| 项 | 必须实际检查 | 不能替代它的证据 |
|---|---|---|
| 链路 | 页面及真实执行符合场景预期；成功场景本轮新产物可打开，预期拒绝/取消场景终态正确且无非法产物 | 步骤绿灯、HTTP200、旧产物、模型自报成功 |
| 数据 | 独立从授权输入核算，范围、版本、时间、单位、筛选、分组及关键数值一致 | 用模型另一段回答或同一工具输出作为标准答案 |
| 内容 | 用户每项要求得到回应，结论有依据，未知与缺条件明确，全文及图文一致 | 命中关键词、出现正确总数、章节标题存在 |
| 呈现 | 浏览器和下载文件分别可读；表格、图、分页和来源能直接使用 | 有图片对象、非空文件、只提取文本未逐页看 |

- 四项各写「通过／不通过／未验」，不适用注明理由；任一适用项不通过或未验，不宣布完成。不采用可用美观分抵消数据错误的总分。
- 数据/权限泄露、错数/错单位/错范围、伪造来源或成果、旧文件冒充新文件、说成功却无成果、执行失败被写成成功，均为硬失败。
- 请求的正文缺失、工具原文充当分析报告、答案前后矛盾、主要图表不可辨认、缺少用户指定交付项，也是不通过；不能降格为「小美观问题」。
- 有环境或证据缺口记「未验」，写明缺什么；不猜代码根因。重放历史文件只能判那份历史产物，不能证明当前代码仍然通过。
- 预期拒答、空结果、驳回、取消或错误回执符合真实情况可通过，未要求文件时产物项不适用；但用户要求生成而执行失败仍不通过，不能把正确错误提示当成功生成。

### 2. 问答、数据分析与生成文本

- 先把问题拆为要求清单，再逐项对照最终答案；先给直接结论，再给必要依据，不堆内部过程、工具名、原始JSON、dtype、堆栈或重复段落。
- 知识问答的关键事实与适用制度要能回到授权原文对应位置；版本、生效时间及适用对象正确。引用文件存在不等于引用支持该结论。
- 无依据、缺条件、结果为空或工具失败时如实说明；不编政策、原因、数据、审批、图或下载链接。事实、推断、建议必须区分。
- 数值独立复算：关键金额与计数全部核对，明细合计与分组/图/正文一致；精度与舍入方式测试前声明，金额按约定小数位，不事后放宽误差。
- 百分比注明分母；同比/环比必须有可比期间。只有单期费用不能写经营趋势、利润变化或因果结论。
- 补问应列出真正缺失的业务条件；错误提示面向用户解释下一步，不让用户自己排版来替代系统已承诺的报告导出。

### 3. 报告及PDF质量

- 以用户用途确定深度：简短统计可简短，但必须含直接结论、关键数值、范围/筛选、来源和所要求图表；不能为了页数制造分析。
- 用户要求分析报告时至少具备：摘要结论、分析范围与口径、核验结果/必要明细、图表及解释、依据充分的发现、局限与必要后续动作。无依据的建议宁可不写。
- 章节有实质内容，不以封面、标题、原始统计日志或「报告结束」冒充完整报告；已生成的有效分析不得在导出时被统计摘要整体覆盖。
- 「实质分析」按需求清单判定：读者能知道答案、对应数据依据、适用边界；例如只有财务200元时明确仅本部门、2条记录及筛选口径，不编跨部门对比。发现与建议不能用通用套话填空。
- 所有关键数值与源数据一致，结论与图相符；每张图有业务标题、单位、筛选/期间及有意义的图注。来源标明输入文件/版本、工作表或可定位数据范围，生成时间不是数据期间。
- 逐页渲染并检查：中文可读，正文与封面层级清晰，无裁切/重叠/孤立标题；表格跨页合理、长标签可读，不丢明细。不因固定模板另造近空白结束页。
- 呈现条件记录为浏览器1440×900、100%缩放；支持窄屏的功能另验390×844。PDF先整页查布局，再100%阅读正文和图标注；正文默认至少10pt、图标注至少9pt或等效清晰可读。仅结束语/时间/免责、无新增业务内容的独立尾页不通过，必要封面不按此规则判坏。
- 图注、正文不显示随机文件名、容器路径、dtype、原始JSON等内部垃圾；下载名使用可理解的业务名称（内部存储可用随机ID）。
- 检查聊天最终答复、审批内容、成果登记、实际PDF四者是否一致；审批通过仅表示授权，不能当作生成成功。不能一边说不支持PDF、一边说已导出。
- Excel单独检查实际工作表、数据类型、行列、公式/结果、金额/日期格式及权限，不把PDF通过外推到Excel。

### 4. 图表质量

- 选择能回答问题的图型：比较用柱图，真实时间序列才画趋势；组成比例须有明确整体。用户明确指定图型时遵从或说明为何无法表达，不偷偷换图。
- 柱图数值轴从0开始，真实负数可向下延伸；禁止3D、扭曲尺度或无说明断轴。折线可非零起点但须明确刻度，不造成夸大误读。
- 图名、分类、数值、单位、期间、筛选与授权输入一致；颜色有语义且不过度，不能仅靠颜色区分。条数、顺序和分组要与表/正文对应。
- 单分类竖柱必须保留左右留白，柱的像素宽/坐标轴内部绘图区像素宽不超过35%，且数值标注不顶边；横柱按柱厚/绘图区高度同样验35%，不是限制数值长度。比值取渲染后图中同一坐标系，不用页面宽或数据单位。用户未指定柱图时可用指标卡。不得添加无权查看的部门或虚构对照让图「好看」。
- 多分类不挤成不可读条纹：长标签换行/横向布局/合理分面；使用Top-N需明确截断及剩余范围，不能静默遗漏。零值、负值、多数量级、相同值和缺失值均应可解释；空数据不得伪造柱。
- 浏览器正常显示尺寸与PDF实际阅读尺寸分别检查：标题/坐标/图例/数值不重叠、不裁切，文字和线条清楚；图不拉伸，图注不是随机PNG名称。
- 生成前核验输入、选图型和布局；生成后核验数据与阅读效果。它们是产品应承担的步骤，不要求最终用户提醒系统「画得好看」。

### 5. 其他功能同类风险

- 上传/预览/OCR：核对实际文字、表格行列、关键数值与原文件；成功状态不能掩盖漏页、错列或数字错识别。下载应保持约定内容与权限。
- 总览/评测报告：数字、样本数、分母、过滤范围及更新时间来自真实记录；样本不足显示不足，不把目标写成已达成，也不拿能打开页面等同评测内容可信。
- 告警/通知：条件、阈值、实际值、对象、时间、原因与操作结果一致；无数据不是正常，未发送不是已通知；接收人和可见范围正确。
- Trace/计算记录：来源、输入版本、筛选、步骤、终态与成果对应同一请求；返回了日志不能冒充计算成功。
- 图谱：关系有可核验来源，主客体/方向正确，无证据不补关系；界面有节点不等于关系可信。
- 成果中心/审批：实际内容、标题、状态及所有者一致；批准/驳回/取消/失败各不相互冒充，重复点击不能交付别人或上一轮成果。

### 6. 复验取样、证据与边界

- 首先复核既有失败产物及其输入、历史日志和实际判据；之后只在确认隔离、安全且没有测量窗口冲突的演示环境，走真浏览器、真PG/Redis、真模型流程。
- 每个具名主成功场景、指定角色各用新的产品业务会话/请求抽样3次（同题2次、同义问法1次），分别报告重复与变体结果；每次核对新成果及四项，不只展示最好的一次。已明确失败可停止该场景的重复，实际次数照实记；边界场景先各1次，不做角色与边界的全笛卡尔积。3次通过只代表本轮抽样，不证明长期稳定。按小功能分批，不反复跑全量门掩盖单点问题。
- 至少覆盖财务经理/管理员的授权差异，单分类、多分类、空结果、长标签/长正文、缺条件、无依据、错误/取消/拒绝；功能相关时再覆盖多工作表、负值/零值/大数量级及版本切换。
- 合成费用表基准：财务仅120+80=200；管理员保留已批准/已支付7行，财务200、销售480、研发420、行政人事210，合计1310；待审批310与已驳回90不得混入。此基准只适用于那份合成表，不外推客户数据。
- 证据集中到一处走查产物目录：原始请求、账号角色与可见范围、源文件/版本、独立期望值、本轮请求ID、运行版本/模型、日志/截图、实际下载文件及SHA256。PDF保留逐页截图，旧失败样例不覆盖。
- 单份复验清单记录：功能/场景、四项判定、具体失败及预期、证据路径、根因（未定位就写未知）、严重程度。漏测明确列出；完整复验前不更新整体质量通过分母。
- 只做复验与诊断，不顺手修产品、不改测试放行、不push、不删除真实数据，不接业主VM或开启远程模型，不并行占用同一测量环境。无安全环境先交历史产物审查与缺口，申请所需权限。
- 执行授权须来自当前用户，绑定环境URL/Compose项目/数据库与存储、具名测试账号/对象及允许动作；安全判断、历史授权和本文件不是操作授权。通知/告警必须确认出口隔离、不连真实收件人/Webhook，未知则未验；测试状态写入与证据目录写入分开说明。独立Agent交复验意见，项目完成状态仍由总控按AGENTS.md确认。
- 不为本标准新增文档自证测试或凭据纸；已有冒烟0退出只代表脚本原覆盖。后续测试改进只针对可见缺陷，保留原反证，依项目流程另做小批量产品修复。

### 7. 已发现的问题与现阶段结论

2026-10-12逐页复核此前财务/管理员各3页PDF：独立核对金额及图数值正确，但正文为统计摘要、缺实质分析，图注使用随机PNG名，结束页近空白；财务单根柱铺满绘图区。本次未改产品或冒烟脚本，故报告质量、单分类图表质量不通过，其他生成质量逐项未验。10-11的V1 9/9与V2 12/12保留为旧判据历史链路结果，不作为本节质量验收结论。
