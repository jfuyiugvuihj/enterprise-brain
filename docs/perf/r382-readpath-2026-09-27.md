### 2.4 归因：三层排除落到索引，另附两条附带读数

1. **不是向量不同源。** 两库 1008 枚 id 零差、逐位相等：`max|Δ|=0.0`、成对余弦最小
   `0.9999998807907104`（`r382_parity.json`）。⇒ 差集不能推给搬库精度。
2. **不是距离算子不同。** 同一枚查询向量做三种精确 KNN 暴力比对：遗留名次与**精确 L2** 集合重合
   44/60、名次全等 8/12；与 cosine 只有 38/60、名次全等 **0/12**；与内积 24/60。且同一枚命中
   满足"遗留报的距离 = pg 报的距离的平方"（`12.315191² ≈ 151.663956`）。⇒ 两侧都按 L2 排，
   只是各自缩放：**名次可比，原始数不可比**，所以本文不出现任何跨引擎比距离的表。
   这条今天不必再靠名次反推：三方的排序口径已一次性现读成表，`l2 / m=16 / ef_construction=100`
   三方**逐格相同**（见 T11）——翻开关不改“最近”的定义。
   顺带一条：库里向量范数 `17.10–23.40`、单位范数 0 枚 ⇒ cosine 与 L2 本来就会排出两套名次，
   这不是缺陷而是算术。
3. **是索引召回。** 同一份向量做精确 KNN，两库的精确 top-5 **12/12 完全相同**；pgvector HNSW
   **12/12 复现精确名次**（recall@5 = **1.0**），Chroma HNSW 只有 **8/12**（recall@5 = **0.7333**）。
   ⇒ 在 1008 枚这一格上，**切读是召回上升**，不是下降。
4. **顺手消掉一型空腿。** 遗留引擎对 3/12 枚真查询向量交回 **0 行**，与 `k` 无关
   （k=1/3/5/10/50 全 0）、与重复调用无关（三次全 0）、与向量微扰无关（×0.999/×1.001/×1.01 全 0），
   未打标签与已打标签两份副本都复现；同题 pg 腿交回 5 行且与精确 KNN 同序。
5. **但两腿的 `ef_search` 不同，这是切读后召回的第一颗雷。** pg 侧运行时 `hnsw.ef_search`
   现读 = **40**（`r382_index_scope.json`；pgvector 出厂默认，
   `app/rag/pg_store.py`、`app/rag/retriever.py` 里 `rg ef_search` 零命中
   ⇒ 读路径从没设过它），遗留引擎配置里是 **100**。⇒ 候选宽度在切读那一刻**缩 2.5 倍**。
   在 1008 枚这一格它没咬人（pg recall@5 仍 1.0），但这正是"1008 太小"的又一条证据：客户真尺寸下
   第一件要量的就是它；切读窗口里应显式 `SET hnsw.ef_search`（或按尺寸定），否则将来召回掉了
   没人知道为什么。**本班没有翻这个值，也不许由本班来翻**——它是配置决策，归总控与业主。
   同一份 JSON 另有一格顺手钉住：沙盒与生产的 DDL、`hnsw.ef_search`、pgvector 版本
   `0.8.6` 逐格相同 ⇒ 本班在沙盒量到的召回口径就是生产那一份（见 T11）。
