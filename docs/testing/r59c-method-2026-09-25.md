## 1. 判据 ①：服务内端到端（真库、真权限、真结果集）

### 1.1 量什么

计划书原话是"服务内端到端没在真库上跑过（今天只在 fake connection 用例下绿过）"。这一格要的读数是：**同一个 principal 打同一枚服务入口，在两个读后端上各跑一遍，逐题比服务交回的最终结果集**。

- 入口：`POST /api/v1/observability/retrieval/debug`（`app/api/v1/observability.py:481`，docstring 原话 "Run one permission-scoped retrieval and return a bounded, replayable report"）。
- 作用域：由鉴权 principal 决定（不是请求方能挑的），内部走 `run_retrieval_debug(..., pipeline=_pipeline(), ...)`。
- 它不生成答案、不进 pandas、不出图 —— 但**每一发仍打模型**（一发查询改写，现值 4.08 s/发，外加最多 `MAX_REWRITES=5` 发 embedding）。别把它当便宜货，预算闸 `--max-requests` 就是为它设的。

### 1.2 怎么算数（列定义）

题集：`tests/fixtures/business_evaluation_100.jsonl` **105 题只读引用**，装载用常驻件 `scripts/check_eval_evidence_coverage.py:load_rows`（自带四道 StructureDrift 闸：105 行 / id 唯一 / must_contain 非空 / 词条总数）。本件不另造题集读法，改一个字它自己就红。

| 列 | 含义 | 纪律 |
|---|---|---|
| `jaccard` | 两侧命中集合的 Jaccard | 双空题一律 `null`，不算 1.0 |
| `same_set` | 集合是否逐枚相同 | 与 jaccard 独立成立，缺一不算对 |
| `first_diff_rank` | 第一个不同的名次（1 基） | 两侧一致时为 `null` |
| `mean_abs_rank_shift` | 共有元素的名次平均绝对位移 | 只在共有元素上算 |
| `kendall_tau` | 共有元素 ≥ 2 枚才给值 | 少于两枚交回 `null`，不硬算 |
| `both_empty` | 两侧都交 0 行 | 单独计数，永不进"一致"栏 |
| `server_ms` / `client_ms` | 服务端耗时 / 含往返耗时 | 代价分解用 `client_ms`（这一项两边都有出处） |
| `answered_by` | 这一发的答复方增量 | 臂身份凭证，见 §1.3 |

命中身份 = `source#chunk_index`。服务端 `_bounded_value` 会把整数过成 float（`chunk_index: 3.0`），本件用 `_as_int` 归一后再拼键 —— 不归一的话两侧永远"不一致"，那是解析错不是召回差（自校钉 P1 守这条）。

### 1.3 臂身份：为什么这一格不可能再被取错样本

上一班（R59）那份读数整份作废，根因不是算错，是**两侧样本都取错了对象**（`docs/testing/r59-recall-reading-2026-09-24.md`；计划书 §9.4）。本件把这一类错变成结构上不可能：

- 本件**不连库、不开 Chroma、不拼 DSN、不猜目录**，只发 HTTP。"读的是哪一库"不由量具声称，由**服务自己的行为作证**。
- 每发前后各读一次 `GET /api/v1/health/details`，取 `search_shape.answered_by` 的**增量**（不是 `last`：一发内部会问多路改写，`last` 只反映最末一问，增量能把"这一发里混着两条腿"的半切态照出来）。
- 三枚合法答复方码逐字取自 `app/rag/retriever.py:82-87`：`chroma` / `hot_index` / `pgvector`。`keyword_scan` 不算凭证 —— 它是向量腿整个下线时的关键词退化，落在哪一臂都不代表"这一臂的引擎答了"。
- 声明与实证不符 ⇒ 该臂 `arm_ok=False`，退出码 3，`compare` 直接**拒绝出对照**（不是降级出数）。配置字符串不算证据，答复方才算。

### 1.4 与 R59b 那 135 题读数的边界（两格各归各，不许混用）

### 1.5 一件必须先说清的口径差：R59b 的"135 题"里有 30 题被数了两遍（本单实测）

`scripts/r59_recall_compare.py:52-53` 的默认题集是 **两枚 fixture 顺次相接**：`business_evaluation_30.jsonl` + `business_evaluation_100.jsonl` ⇒ 135 行。本单逐 id 复算过这两份文件：

- `business_evaluation_100.jsonl` 实有 **105 行**（名字叫 100，行数是 105 —— `check_eval_evidence_coverage.py` 的四道闸认的就是 105）；
- `business_evaluation_30.jsonl` 的 30 枚 id **全部**包含在那 105 枚里，且**题面逐字相同**（复算：同 id 不同题面 = 0 枚）；
- ⇒ R59b 的"135 题"真实形状是 **105 枚唯一题，其中 30 枚被算了两次**。计划书 §10 那句"24 题去重后 21 枚"正是这件事漏出来的尖。

对本件的影响与纪律：

- R59c 只引用 `business_evaluation_100.jsonl` ⇒ **分母 105**，且每题只发一次（每档每重发一次）。所以本件的"不一致 N 题"与 R59b 的"67/135"**不能直接对数**，只能对**题号集合**（题号才是可比的，行数不是）。
- 反过来，谁要把本件读数凑成"135 口径"去和旧文对齐，就是造出第二份会过期的数字 —— 本件不提供这个功能，也不许在文档里这么换算。
- 这一条不改 R59b 的**方向结论**（它的 67 题不一致、24 题空答复是按行报的，重复 30 题只会让同一枚症状计两遍，不会把 0 变 5），但**任何按 135 算的百分比都要按 105 重读一遍**才算诚实。


## 2. 判据 ②：「热集让路」的代价 —— 定义、取数口径、预算公式

### 2.1 「热集」是什么（先把名词钉死，别量错东西）

「热集」= 进程内常驻向量索引 `app/rag/hot_index.py`（R44 交付、R79 补观测与 float32 下沉）：

- 开关：环境变量 `HOT_INDEX_ENABLED`，取值在 `TRUE_VALUES = {"1","true","yes","on"}`（`app/rag/hot_index.py:42,151-154`）里才算开；**未设置、空串、任何不认识的值一律算关**。
- **今天生产 = 关**：`deploy/.env.server` 里 `HOT_INDEX_ENABLED` 这一行**不存在**（本单实测 `rg` 零命中）。所以计划书 §9.3 ② 说的"让路代价"，量的是**开了之后会省多少、切读之后省不到**这个差，不是今天已经在付的账。
- 取数口径：暖机走 `_warm_hot_index`（`app/rag/retriever.py:1016`），一次 `collection.get` 读全库元数据 + 一次带 `embeddings` 的 `get` 把向量搬进进程。**只读不写，一次 embedding 都不多发**（读回来的就是库里那一份）。
- 常驻上限 `HOT_INDEX_MAX_CHUNKS` 默认 20 000、花名册页 `HOT_INDEX_ROSTER_PAGE` 默认 1 000、花名册 TTL `HOT_INDEX_ROSTER_TTL_SECONDS` 默认 300 s、暖机失败退避 60 s。生产全库 1008 枚 ⇒ **整库都能常驻**（这就是这一格能量得动的前提）。
- 让路机制：`_hot_hits`（`app/rag/retriever.py:1118`，判定在 `:1129-1133`）—— `pgvector_reads_enabled()` 一真，整层立刻让路并记原因码 `hot_index_read_backend_switched`（不是故障，单独一枚码）。

### 2.2 为什么这一格必须三臂（缺一臂就少一项）

"切读"一次改了两件事：**换引擎**（Chroma→PGVector）与**撤加速层**（热集让路）。两件事混在一个差里就量不出代价 ⇒ 拆成三臂：

| 臂 | 读后端 | `HOT_INDEX_ENABLED` | 说明 |
|---|---|---|---|
| A2 `chroma-hot` | chroma | on | 唯一需要翻 env 才存在的臂 |
| A1 `chroma-cold` | chroma | 未设 | **今天生产的形状**：外部向量库裸奔 |
| B `pgvector` | pgvector | 任意（必然让路） | 翻不出来，见 §0 与操单 §1.1 |

### 2.3 代价公式（脚本能量出来的列，不是散文）

全部用 **paired（同题同号配对）**，与 `--base` 选谁无关；三项都是「减数臂 − 被减臂」的有符号差：

```text
热集收益   hot_gain_ms        = paired(A1 - A2)   —— 让路之前热集原本省下多少
切读裸代价 switch_cost_ms    = paired(B  - A1)   —— 只换引擎、两侧都没有热集
净让路代价 net_yield_cost_ms = paired(B  - A2)   = switch_cost_ms + hot_gain_ms
```

- 恒等式 `net = switch_cost + hot_gain` 由 selfcheck 的 **P11** 钉住（注入真值 204.5 / −100.0 / 104.5，误差列 `identity_error_ms` 进产物）。
- 每一臂对 `--base` 还各给一组 `paired_delta_ms`（median / p25 / p75 / n），供逐题下钻。

### 2.4 噪声地板：不给重发就没有"代价"，只有"方向"

`noise_floor_ms_p95` 只来自 `--repeats >= 2`（同臂同题组内散布的 p95）。判定：

- `|代价| > 地板` ⇒ `RESOLVED`；
- `|代价| <= 地板` ⇒ **`NOT_RESOLVED`** —— 这一格写"量不出"，绝不把那个小数当代价进档案；
- 没给重发 ⇒ `NO_NOISE_FLOOR` / `NOISE_FLOOR_MISSING`，产物如实写 null，**不许拿两臂硬凑三项**、不许拿方向冒充代价。

### 2.5 命中分布侧（②的另一半：让路不只是变慢）

热集是**精确全量扫描**（O(常驻条数)，见 `docs/handoff/2026-09-20-unblock-map.md` 对 R44 的订正：计划书那句 0.0015 ms 的前提是 HNSW），而外部向量库走 ANN。所以让路换掉的**不只是延迟，还有算法**：名次与集合都会动。产物因此同时给：

- 热集实际服务占比（`answered_by = hot_index` 的增量份额）；
- 让路影响题数：其中**名次变了**几题、**集合变了几题**；
- 逐题 `jaccard` / `first_diff_rank` / `kendall_tau`（与 R59b 同名同键，可逐列对差）。

## 3. 判据 ③：选择性权限过滤

### 3.1 现库为什么量不到（真实形状，不是借口）

计划书原话：本库 `classification` 全 = 1、`department` 全 = `''`。谓词由 principal 决定（`app/rag/filters.py`：管理员只带 `classification $in [1..clearance]`，普通人再加 `department $in [...]`），于是：

- 全命中谓词 ⇒ 两侧答案必然相同（量不出差）；
- 全零命中 ⇒ 两侧一致地空（**PG 侧没有漏放行**，但同样量不出召回差）；
- 跑分账号 `evalbot` 大概率走 `administrator_scope`（这一枚谓词不带部门条件）⇒ 连"部分放行"都构造不出来。

⇒ 「选择性强过滤下的召回差」这一格**必须换语料才能量**，而换语料要碰库。本单不碰库，交付三样料：**沙盒语料构造脚本 + 两侧谓词对照判据 + 业主需批的 DDL/DML 清单**（`scripts/r59c_sandbox_corpus.py`，`plan` 子命令，零执行）。

### 3.2 两道当场就有效闸（不需要沙盒）

1. **影子越权哨**（`shadow_permission_check`）：拿响应自带的 `permission_filter` 与逐条命中的 `classification` / `department` 独立再判一次，越权行 = 硬红，逐格计数进 `cells.9.3-3.over_permission_rows`。
   - 它不是产品判定的第二份实现：不决定谁能看什么，只对"已经交出来的东西"提异议。
   - 谓词形状看不懂 ⇒ 判 `unknown`，**不判干净**。响应里那枚恒真的 `permission_checked: True` 是服务端自述，本件不采信。
2. **可选性硬闸**（`census` 子命令 + 汇总里的 `selectivity_screen`）：普查 `GET /api/v1/documents/catalog` 里 distinct `department` / `classification` 分布，配逐题 `scope_reason`。判据：放行块数必须落在 (0, 全库) 开区间且 department 至少两个取值；不满足就整格 `NOT_MEASURED` 并写明"是语料没有可选性"，**不是"入口跑过了"**。

### 3.3 沙盒侧判据 J-1〜J-5（`verify` 子命令）

| 判据 | 内容 | 红的含义 |
|---|---|---|
| J-1 可选性 | 每一档 principal 的谓词只放行**一部分**块 | 语料没选择性，后面全不成立 |
| J-2 不越权 | 任何交回的块都必须落在该 principal 允许集内 | 越权 = fail-closed 优先于召回，直接红 |
| J-3 等于精确解 | 索引腿交回 == 该允许集内的精确 top-k | HNSW 在选择性预过滤下丢 neighbor |
| J-4 两侧一致 | chroma 侧与 pgvector 侧逐题集合/名次对差 | 真召回差，交人判读 |
| J-5 降级不算通过 | 走关键词退化 / 臂身份未证实 / 缺读数 ⇒ 一律 `NOT_MEASURED` | 不许把空表印成通过 |

### 3.4 合成向量的边界（这一格量的是什么、不量什么）

沙盒语料是 **LCG 合成的 768 维向量**（4 部门 × 3 密级，默认 48 块）。它量的是**谓词算术与选择性预过滤**（放行比例、允许集、精确 top-k、索引腿丢行），**不量语义质量**。任何"合成沙盒语义召回好/坏"的结论都是越界，`BATCH.md` 里已把这条写成业主需拍板的第三件事。

### 3.5 沙盒的三条硬边界（脚本里是守卫，不是倡议）

- 库名必须是 `enterprise_brain_r59c` 前缀且 ≠ 生产库名；撞上就 **print + 退出码 3 且不产任何文件**（自校钉 S10）。每段 SQL 自带 `current_database()` 守卫。
- 正向批单里**零 `DROP`**（S11）；只读探针 `probes.sql` **零写入**，只有 `SELECT` + `SET`（S12）。
- 本班不执行任何 DDL/DML：`plan` 的产物里 `"executed": "NOTHING"` 是事实陈述，不是免责声明的替代品。

## 5. 长跑纪律（这一发要 4 s 以上、整臂上百发）

- **产物**：`collect` 写 append-only JSONL，逐行 `flush` + `os.fsync`；崩了不丢已发的数。
- **续跑**：`--resume` 只认 `status=ok` 的格（键 = 题号 + top_k 档 + 重发序号），失败的格会重打。
- **重跑**：`--attempts N`（单发失败重打，带 `--retry-sleep`），连续 5 发失败自动停手，不把窗口烧在死服务上。
- **预算闸**：`--max-requests`（默认 260）超限即停并打印续跑命令行 —— 每发都打模型，没有闸就等于没有刹车。
- **限速**：`--gap-seconds`（默认 0； `MODEL_MAX_CONCURRENCY=1` 的机器上别开并行）。
- **中断**：Ctrl-C ⇒ 退出码 130，已发读数留在盘上，`--resume` 接着跑。
- **档位**：`--top-k 5,10,20` 每一档都是**独立重发**，不是拿前缀截 —— 截前缀会把"k 变大时名次怎么动"这件事量成假的。超过 `MAX_TOP_K=20` 的档位本机直接拒收（服务端会 clamp，读数就不是那一档了）。
- **口径不手抄**：`server_limits()` 用 ast 从 `app/api/v1/observability.py` 现读 `DEFAULT_TOP_K` / `MAX_TOP_K` / `MAX_QUERY_CHARS` / `MAX_EXCERPT_CHARS` / `MAX_REWRITES`；产品改了常数，本件跟着变，不会留下第二份过期数字。
- **可辨认**：`request_id` / `trace_id` 一律 `r59c-<arm>-<题号>-k<档>-r<次>-<8hex>`，事后 `grep -c "r59c-" data/traces/events.jsonl` 就能把这窗的账点清。

## 6. 零写入承诺的真实边界（不掩饰）

`retrieval/debug` 不发答案、不进 pandas、不出图，但**每一发在服务侧留下两笔账**：

- `run_retrieval_debug` 经 `trace_store.record_event`（`app/rag/debug.py:66`）写一条 `retrieval.completed`；
- 路由收尾记一条 `retrieval/debug` 的 allowed 审计（`app/api/v1/observability.py:543`），而 `administrator_scope` 每一发还会经 `record_retrieval_scope` 落一行。

⇒ "只读"对**业务数据**成立，对 **trace / audit 台账不成立**。本件的处置是让这些账可辨认、可清点（`r59c-` 前缀），并在操单里给出事后清点步骤。要真零写入得另立单改服务端，不在本单写域。
