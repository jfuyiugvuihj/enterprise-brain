# MYBI数据源接入手册

## 一、支持的数据源类型
MYBI平台支持接入以下数据源：
- MySQL / PostgreSQL / Oracle / SQL Server
- Hive / ClickHouse
- Kafka（实时流）

## 二、接入步骤

### 步骤1：填写连接信息
在“数据源管理”页面点击“新增数据源”，根据所选类型填写以下信息：
- **数据源名称**：自定义标识，建议包含业务含义
- **连接地址**：主机IP或域名
- **端口号**：各数据源默认端口（MySQL:3306, PostgreSQL:5432, Oracle:1521, SQL Server:1433, Hive:10000, ClickHouse:8123, Kafka:9092）
- **数据库名称**：目标数据库/实例名
- **用户名/密码**：具有相应权限的数据库账户

### 步骤2：测试连通性
填写完成后点击“测试连接”，系统将校验：
- 网络可达性
- 认证信息有效性
- 必要权限是否满足

若测试失败，请检查防火墙、端口开放、账户权限等配置。

### 步骤3：选择同步策略
根据业务需求选择数据同步模式：

| 策略 | 适用场景 | 说明 |
|------|----------|------|
| 全量 | 初次同步或数据量小 | 每次覆盖目标表全量数据 |
| 增量 | 仅需新增/修改数据 | 基于时间戳或自增ID字段过滤 |
| CDC | 实时捕获变更 | 依赖数据库日志（如MySQL binlog） |

**注意**：Kafka数据源仅支持实时流模式，无需选择同步策略。

### 步骤4：配置调度周期
- **一次性**：手动触发，适合全量初始同步
- **定时调度**：设置cron表达式或选择频率（分钟/小时/天）
- **实时监听**：CDC模式或Kafka流自动持续同步

## 三、注意事项

### MySQL CDC（变更数据捕获）
- 必须开启binlog，且设置为`ROW`模式
- 检查参数：`log_bin=ON`, `binlog_format=ROW`
- 建议保留binlog至少24小时，避免同步中断后丢失数据

### Oracle 权限要求
- 需授予`SELECT ANY TABLE`权限
- 对于CDC场景，还需`SELECT ON V_$LOG`和`SELECT ON V_$ARCHIVED_LOG`

### ClickHouse 访问配置
- 需开放HTTP端口（默认8123）
- 确认用户具有`SELECT`权限
- 建议使用`readonly`账户避免误写操作

### 其他通用建议
- 生产环境建议使用只读账户
- 大表全量同步前评估数据量，避免影响源库性能
- Kafka接入需提前创建Topic并确认消息格式（JSON/Avro等）
