# 研发中心代码规范 V2

## 一、通用规范

所有编程语言必须遵守以下基本规则：

- **缩进**：使用4个空格，禁止使用Tab字符。
- **行宽**：单行代码不超过120个字符，超出应换行。
- **文件编码**：统一使用UTF-8（无BOM）。
- **行尾**：统一使用LF（Unix风格），禁止使用CRLF。
- **命名规则**：
  - 类名/结构体名/枚举名：大驼峰（如 `UserService`）
  - 方法名/函数名/变量名：小驼峰（如 `getUserInfo`）
  - 常量：全大写 + 下划线分隔（如 `MAX_RETRY_COUNT`）

## 二、Java 规范

基于Spring Boot最佳实践，额外要求：

- **日志输出**：禁止使用 `System.out.println()`，必须使用SLF4J + Logback，通过 `LoggerFactory.getLogger` 获取Logger。
- **异常处理**：禁止吞没异常。捕获异常后必须至少执行以下之一：记录日志（`log.error`）或重新抛出（可转换为自定义异常后抛出）。空catch块视为违规。
- **依赖注入**：优先使用构造器注入（`@RequiredArgsConstructor`），避免字段注入。
- **Controller层**：方法返回统一封装 `Result<T>` 对象，使用 `@Validated` 校验请求参数。
- **Service层**：事务方法使用 `@Transactional(rollbackFor = Exception.class)`。

## 三、Python 规范

严格遵循PEP8，并增加以下要求：

- **类型注解**：所有函数参数和返回值必须使用Type Hints，如 `def get_user(user_id: int) -> User:`。
- **异步函数**：异步函数命名必须以 `async` 结尾，例如 `fetch_data_async()`。禁止在同步函数中使用 `async` 关键字。
- **日志**：使用 `logging` 模块，禁止 `print()`。配置日志级别（INFO及以上）。
- **导入顺序**：标准库 → 第三方库 → 本地模块，每组之间空一行，使用绝对导入。

## 四、Go 规范

以 `gofmt` 格式化为基础，增加以下约束：

- **格式化**：所有Go代码必须通过 `gofmt` 格式化，提交前强制检查。
- **init函数**：避免滥用 `init()`。仅允许在以下场景使用：注册数据库驱动、解析全局配置（且配置不可变）。业务逻辑、依赖初始化不得放入 `init()`，应使用显式初始化函数如 `InitApp()`。
- **错误处理**：函数返回错误时，调用方必须处理（检查并返回或记录日志）。禁止使用 `_` 忽略错误，除非在明确注释说明的场景。
- **命名**：包名小写单数，避免 `utils`、`common` 等模糊命名。接口名以 `er` 结尾（如 `Reader`、`Writer`）。

## 五、通用检查项

- 所有代码提交前需通过静态检查工具（如 Checkstyle、pylint、golint）。
- 变量命名应具有业务含义，禁止使用单字母（循环变量 `i`、`j` 除外）。
- 注释：公共API必须写文档注释（Java：Javadoc，Python：docstring，Go：注释以函数名开头）。代码中避免无意义注释。
